Step 01
It starts at the slash

Most people never type /. It's a whole discovery surface — 60+ built in. /init writes your project memory, /review and /security-review audit your diff, /insights shows you how you prompt, /agents, /mcp, /plugin open the rest.

/init /insights /review /security-review /agents /mcp /plugin
Quick show of hands
Who's ever just typed "/" to see what's there?

And — what's the most useful command you've found that the rest of us might not know about?

Start here
Hold up a mirror: /insights

The easiest first win isn't a fancier prompt — it's seeing how you already prompt. /insights reads your last 30 days of local sessions and writes a report on your style: where Claude misreads you, where you over- or under-specify. It hands back copy-paste rules for your CLAUDE.md tuned to your own friction. Nothing leaves your machine.

Analyses your own history Local only — no upload Actionable, not just charts
Step 02
Agree the plan first

/plan (or Shift+Tab) makes the agent propose a plan and wait before it touches anything. Add "think" / "think hard" / "ultrathink" to buy more reasoning. This is the cleanest vibe-to-engineering moment: same prompt, but you approve before code is written.

Propose Review Approve Then build

Step 03
Give the agent a memory

CLAUDE.md is the agent's persistent context — conventions, architecture, "always run the linter." It's what turns a stateless chat into something that knows your project. /init generates a first draft. Highest-leverage, zero-setup first step.

Conventions Architecture notes Do's & don'ts Our Vibehuus repo has one
Quick show of hands
Who has a CLAUDE.md or rules file in their repo right now?

What's in it — and has it actually changed the quality of what comes back?

Step 04
Delegate & compose

Skills package invocable instructions that load only when needed (a markdown file in .claude/commands/ becomes a slash command). Subagents are specialized Claude instances with their own context window and scoped tools — run a few in parallel and keep their noisy output out of your main thread.

Skills = reusable moves Subagents = a small team /agents to manage them
Over to you
Anyone running subagents or parallel agents?

What do you delegate — reviews, research, tests? And does it actually save time, or just move the cleanup around?

Step 05
Guardrails that can't hallucinate

Hooks are deterministic scripts that fire on events (e.g. PreToolUse). Real code, not prompts — so they can veto a dangerous bash command or scan a write for secrets, every time. This is the step that makes it real engineering.

Block dangerous commands Scan for secrets Enforce, don't suggest
Over to you
Has an agent ever done something that scared you?

Deleted the wrong thing, force-pushed, leaked a key? What guardrail do you wish you'd had — or have since added?

Step 06
Scale it to a team

MCP connects the agent to your tools and data. Plugins bundle skills, subagents, commands, hooks and MCP servers into one installable unit your whole team shares — so the standards travel, not just live in one person's setup.

MCP = tools & data Plugins = shared, versioned setup
So what is "agentic engineering"?
Two shifts, not a pile of features
  • Doing → supervising. You give an objective plus constraints; the agent runs the loop, you review.
  • Interactive → autonomous. Run it headless (claude -p … --max-turns N) and wire it into GitHub Actions — it wakes on a PR, reviews, fixes, commits.
A working definition
Designing repeatable processes where agents run multi-step work inside constraints you set.

Interactively when you're supervising. Autonomously when you're not.

Over to you
Would you let an agent commit to your repo unattended?

On a PR, in CI, at 3am? What would have to be true first for you to take your hands off the wheel?

The on-ramp — don't start at 3am
First steps
  • Interactive + structured — plan mode + CLAUDE.md + /review. Zero infra, everyone today.
  • Orchestrated — subagents + skills. Delegate and compose.
  • Autonomous — headless in CI / GHA, once the guardrails are in place.

The punchline: the autonomous step is only safe because of the guardrails from the earlier ones. They're the precondition, not the polish.
